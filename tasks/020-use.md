# 020: The `use` builtin

Depends on: 019.

## Task

Add `use "file";`, which runs a source file inside the current session.

## Context

- Read: `interp/interp.go`
- Change: `interp/interp.go`, create `interp/use_test.go`
- `use` needs the session, so define it in `interp.New`, not in the `builtins` package: a `value.Builtin` named `use` whose `Fn` closes over the `*Interpreter`.
- Behavior of `use path`:
  1. Read the file. On failure return a plain error: `use: cannot read <path>`.
  2. Write `[opening <path>]` and a newline to the session's `out`.
  3. `SplitInput` the contents. For each chunk call `in.Eval(chunk)`; write each result's `Line(Milestone >= 2)` and a newline to `out`. On an error, stop and return it.
  4. Non-whitespace `rest` after the last chunk: return the error `use: unexpected end of input`.
  5. Return `value.Unit{}`.
- Type string for later: `string -> unit`. Keep a note of it in a comment; task 029 registers it.
- Careful: `use` runs while an outer `Eval` is in progress. The outer `Eval` must commit to the environment that the file's declarations produced, not overwrite it with its own frame. Simplest correct approach: in `Eval`, build each frame on top of the current `in.env` at the moment the declaration starts, and when the declaration succeeds, if `in.env` changed during execution (a `use` ran), make the new frame's parent the changed `in.env`. Add a `SetParent` method to `env.Env` if you need one.

## Done when

`go test ./interp/ -run TestUse -timeout 30s` passes: write a temp file containing `val a = 41;\nfun inc x = x + 1;\n`; `Eval` of `use "<path>";` writes `[opening <path>]`, `val a = 41`, `val inc = fn` to `out` and returns `val it = ()`; then `Eval("inc a;")` gives `val it = 42`. A missing file returns an error and the session still works afterward.
